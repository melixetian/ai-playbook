# Часть 1. Грамматика промптинга

## Одна идея: промпт — не «просто текст»

Промпт — это инструкция для машины. У него есть структура, правила и ловушки. Как у предложения в русском языке есть подлежащее, сказуемое и дополнение — у промпта есть **7 блоков**.

---

## 7 блоков хорошего промпта

```
Плохой промпт (1 блок):
  "Напиши парсер"
  → Парсер ЧЕГО? На каком ЯЗЫКЕ? С тестами? Без?
  → Модель угадывает. Обычно — мимо.

Хороший промпт (7 блоков):
  👤 Роль:         "Senior Python Developer"
  📦 Контекст:     "Python 3.12, stdlib, pytest"
  ⚡ Задание:       "count_words(text:str) → dict[str,int]"
  🚫 Ограничения:  "Без Counter. Без regex."
  📐 Формат:        "JSON: {code, tests}"
  📎 Образец:       "count_words('кот и кот') → {'кот':2, 'и':1}"
  ✓ Проверка:       "Пустая строка → {}?"
  
  → Каждое слово однозначно.
  → Модель пишет РОВНО то, что нужно.
```

**Запомните таблицу:**

```
┌───┬───────────────┬────┬───────────────────────────────────┐
│ № │ Блок          │    │ Вопрос                            │
├───┼───────────────┼────┼───────────────────────────────────┤
│ 1 │ Роль          │ 👤 │ КТО отвечает?                     │
│ 2 │ Контекст      │ 📦 │ В КАКОЙ среде?                    │
│ 3 │ Задание       │ ⚡  │ ЧТО сделать?                      │
│ 4 │ Ограничения   │ 🚫 │ Чего НЕ делать?                   │
│ 5 │ Формат        │ 📐 │ КАК выглядит ответ?               │
│ 6 │ Образец       │ 📎 │ ПРИМЕР результата?                │
│ 7 │ Проверка      │ ✓  │ ЧТО проверить?                    │
└───┴───────────────┴────┴───────────────────────────────────┘
```

## 3 ловушки промптинга

### Ловушка 1: Омонимия — слово с двумя значениями

```
❌ "Создай сервис"

   "сервис" = ?
     • Python-класс (OrderService)
     • Микросервис (payments-service)
     • Systemd-демон
     • gRPC-сервис
   
   → Модель выбирает СЛУЧАЙНО

✅ "Создай класс OrderService с методом create_order()"

   → Одно значение. Модель знает точно.
```

### Ловушка 2: Пресуппозиция — скрытое допущение

```
❌ "Почему мой код медленный?"
   
   Скрытое допущение: код ДЕЙСТВИТЕЛЬНО медленный.
   Модель «найдёт» причины, даже если код быстрый.

✅ "Есть ли проблемы с производительностью? Если да — какие?"
   
   Нет допущения. Модель может ответить «нет».
```

### Ловушка 3: Импликатура — подразумеваемое

```
❌ "Напиши production-ready код"
   
   Вы подразумеваете: тесты, логирование, типизация, обработка ошибок.
   Модель «услышит» половину. Какую — каждый раз разную.

✅ "Напиши код с: обработкой ошибок, логированием через structlog,
    type hints (mypy --strict), 5 pytest-тестами"
   
   Всё ЯВНО. Модель не пропустит.
```

**Правило:** В промптинге **явное ВСЕГДА надёжнее подразумеваемого**.

---

## Почему ограничения сильнее приказов

```
"Напиши сортировку"                → ~20 вариантов
+ "Без sorted()"                   → ~15 вариантов
+ "Без рекурсии"                   → ~8 вариантов
+ "O(n log n)"                     → 2-3 варианта

Три запрета сузили 20 вариантов до 2.

ЗАПРЕТ отсекает целый КЛАСС ответов.
ПРИКАЗ выбирает один из оставшихся.

→ Сначала запреты, потом приказы.
```

---

## Формат ответа экономит деньги

```
Выходные токены в 4 раза ДОРОЖЕ входных.
93% стоимости вызова — это ОТВЕТ модели.

Длина ответа зависит от ВАШЕГО промпта:

  Свободный текст: 100% токенов
  JSON:             55% токенов (-45%!)
  Одно значение:    10% токенов (-90%!)

Добавьте формат → ответ станет короче → вы платите меньше.
```

---

## PQS — оценка качества промпта

```
PQS = число от 0 до 1, которое можно посчитать ДО отправки.

  0.00–0.40 → 🔴 плохой   (retry 50-90%)
  0.40–0.70 → 🟡 средний  (retry 20-50%)
  0.70–0.85 → 🟢 хороший  (retry 5-20%)
  0.85–1.00 → 🟢 отличный (retry < 5%)

"Напиши парсер"              → PQS ≈ 0.15 → 85% retry
"Sr Py Dev. Py 3.12..."     → PQS ≈ 0.87 → 5% retry

PQS = линтер для промптов. Как ESLint, но для инструкций к LLM.
```

## 5 рычагов экономии

```
┌────────────────────────┬─────────┬──────────────────────┐
│ Рычаг                  │ Эффект  │ Усилие               │
├────────────────────────┼─────────┼──────────────────────┤
│ Формат → JSON          │ -45%    │ 1 минута             │
│ Убрать омонимы (DI↑)   │ -37%    │ 5 минут              │
│ Добавить запреты (II↑) │ -17%    │ 2 минуты             │
│ Temperature → 0        │ -15%    │ 10 секунд            │
│ Короткий образец       │ -15%    │ 1 минута             │
├────────────────────────┼─────────┼──────────────────────┤
│ ВСЁ ВМЕСТЕ             │ -73%    │ ~9 минут             │
└────────────────────────┴─────────┴──────────────────────┘

9 минут работы → -73% стоимости КАЖДОГО вызова.
```

# Часть 2. Грамматика скиллов

## Одна идея: скилл — не промпт

```
Промпт:  вы рядом, видите ответ, можете поправить.
Скилл:   работает БЕЗ вас, ТЫСЯЧИ раз.

Последствия:
  1 лишний токен в промпте = 1 лишний токен
  1 лишний токен в скилле × 1000 = 1000 лишних токенов

  1 омоним в промпте = 1 неточный ответ (переспросите)
  1 омоним в скилле × 1000 = 1000 разных интерпретаций

→ К скиллу нужно относиться СТРОЖЕ, чем к промпту.
```

---

## 8 секций скилла

7 блоков промпта превращаются в **8 секций** скилла. Добавляется WORKFLOW (пошаговый алгоритм), а ограничения усиливаются до абсолютных запретов (NEVER).

```
┌───┬─────────────────┬──────────────────────────────────────┐
│ № │ Секция          │ Что делает                           │
├───┼─────────────────┼──────────────────────────────────────┤
│ 1 │ 🎭 IDENTITY     │ Кто ты + когда активируешься         │
│ 2 │ 📦 CONTEXT      │ Стек, версии, пути к файлам          │
│ 3 │ 🚫 ANTI-PATTERNS│ NEVER-запреты (В НАЧАЛЕ!)            │
│ 4 │ ⚙️ CAPABILITIES │ Что умеешь (конкретные действия)     │
│ 5 │ 🔄 WORKFLOW     │ Как делаешь (алгоритм по шагам) ←NEW │
│ 6 │ 📐 OUTPUT FORMAT│ Шаблон результата (не описание!)     │
│ 7 │ 📎 EXAMPLES     │ Ссылки на примеры (не inline!)       │
│ 8 │ ✅ VALIDATION   │ Чек-лист самопроверки (В КОНЦЕ!)     │
└───┴─────────────────┴──────────────────────────────────────┘
```

---

## Порядок секций — не случайный

```
Модель запоминает текст НЕРАВНОМЕРНО:

  НАЧАЛО ████████████ — ПОМНИТ отлично
  СЕРЕДИНА ░░░░░░░░░ — МОЖЕТ ЗАБЫТЬ
  КОНЕЦ ████████████ — ПОМНИТ отлично

Поэтому:
  ANTI-PATTERNS → в начало (забытый запрет = инцидент)
  CAPABILITIES, WORKFLOW → в середину (забытый шаг = поправимо)
  VALIDATION → в конец (последнее действие = проверка себя)
```

---

## Каждая секция за 30 секунд

### IDENTITY — кто ты

```
Формула: [Роль] for [Область]. Active when: [триггеры].

❌ "Ты — опытнейший специалист мирового уровня 
    с глубочайшими познаниями..."            (20 tok, 0 информации)

✅ "DB migration specialist for payments backend.
    Active when: migration, schema change."  (10 tok, ВСЯ информация)
```

### CONTEXT — где работаешь

```
Формула: Stack: [аббревиатуры с версиями]. [Пути к файлам].

❌ "В нашей компании мы используем язык программирования 
    Python версии 3.12 для разработки..."    (30 tok)

✅ "Py 3.12, FastAPI 0.115, SA 2.0 async, PG 16, pytest.
    Configs: YAML in configs/alerts/"         (15 tok)
```

### ANTI-PATTERNS — чего НИКОГДА не делать

```
Формула: NEVER [глагол] [объект] — [альтернатива].

❌ "Желательно не удалять алерты"
   → Модель: "желательно = необязательно" → УДАЛИТ

✅ "NEVER delete alerts without approval."
   → Модель: "NEVER = абсолютный запрет" → НЕ удалит

Три уровня:
  🔴 NEVER  → для ANTI-PATTERNS (нарушение = инцидент)
  🟡 MUST   → для WORKFLOW (нарушение = плохо)
  🟢 SHOULD → для VALIDATION (нарушение = неидеально)
  ❌ "Желательно" → ЗАПРЕЩЕНО в скиллах (модель игнорирует)
```

### CAPABILITIES — что умеешь

```
Формула: [Глагол] [Конкретный объект] [Инструментом]

❌ "Помогаю с мониторингом"
   → "мониторинг" = алерты? дашборды? логи? трейсинг? всё?

✅ "1. Create/modify Prometheus alerts
    2. Create Grafana dashboards
    3. Configure Vector log pipelines"
   → Три конкретных действия, ноль омонимов
```

### WORKFLOW — как делаешь (НОВАЯ секция, которой нет в промпте)

```
Формула: нумерованные шаги, каждый начинается с ГЛАГОЛА

❌ "Когда нужно создать алерт, сначала желательно проверить
    существующие, потом создать конфиг..."     (проза)

✅ "1. Check existing: configs/alerts/{service}/
    2. Create YAML per OUTPUT FORMAT
    3. Validate: `promtool check rules {file}`
    4. Test → prestable → production"          (алгоритм)

Почему есть в скилле, но нет в промпте:
  Промпт: вы рядом, уточните КАК
  Скилл: вас нет — алгоритм должен быть ЯВНЫМ
```

### OUTPUT FORMAT — шаблон результата

```
❌ ОПИСАНИЕ (модель ИНТЕРПРЕТИРУЕТ → каждый раз по-разному):
   "Результат должен содержать JSON с полями line, severity, fix"

✅ ШАБЛОН (модель ЗАПОЛНЯЕТ → каждый раз одинаково):
   {"issues":[{"line":int,"severity":"critical|warning","fix":str}]}
   NO markdown wrap. NO extra fields.
```

### EXAMPLES — только ссылки

```
❌ Inline-пример: 300 токенов КАЖДЫЙ из 1000 вызовов = 300,000 tok
✅ @examples/alert.yaml: 3 токена × 1000 = 3,000 tok

Экономия: 99%. Файл подтягивается ТОЛЬКО по необходимости.
```

### VALIDATION — чек-лист в конце

```
❌ "Всё ли правильно?" → субъективно, непроверяемо
✅ "□ Has runbook URL?
    □ `for` ≥ 5m?
    □ Passes promtool?"  → каждый пункт = да/нет

Повышает качество на 10-20% БЕСПЛАТНО.
Модель перечитывает свой ответ и ловит ошибки.
```

# Часть 3. Связь двух грамматик

## 7 блоков промпта → 8 секций скилла

```
ПРОМПТ (7 блоков):              СКИЛЛ (8 секций):

👤 Роль                     →    🎭 IDENTITY (+триггеры)
📦 Контекст                 →    📦 CONTEXT (+пути, +бюджет)
⚡ Задание                   →    ⚙️ CAPABILITIES (что умеешь)
                                 🔄 WORKFLOW (как делаешь) ← НОВАЯ!
🚫 Ограничения              →    🚫 ANTI-PATTERNS (только NEVER!)
📐 Формат                   →    📐 OUTPUT FORMAT (шаблон!)
📎 Образец                  →    📎 EXAMPLES (только ссылки!)
✓ Проверка                  →    ✅ VALIDATION (чек-лист да/нет)
```

**Что изменилось и почему:**

```
1. Задание РАЗДЕЛИЛОСЬ на две секции (ЧТО + КАК)
   Промпт: вы рядом, уточните КАК
   Скилл: вас нет — нужен явный алгоритм

2. Ограничения УСИЛИЛИСЬ (NEVER вместо «без»)
   Промпт: ошибку увидите и поправите
   Скилл: ошибка × 1000 раз без контроля

3. Ограничения ПЕРЕМЕСТИЛИСЬ (позиция 4 → 3)
   Промпт: ограничения ПОСЛЕ задания
   Скилл: запреты ДО задания (attention!)

4. Формат УСИЛИЛСЯ (шаблон вместо описания)
   Промпт: описание ОК, вы проверите структуру
   Скилл: шаблон гарантирует структуру × 1000 раз

5. Примеры ОГРАНИЧИЛИСЬ (только ссылки)
   Промпт: inline ОК, один раз
   Скилл: inline × 1000 = 300,000 токенов впустую

6. Проверка ФОРМАЛИЗОВАЛАСЬ (чек-лист да/нет)
   Промпт: "проверь edge cases" ОК
   Скилл: "□ Has runbook?" — конкретный критерий
```

**Общий принцип:**

```
ПРОМПТ → СКИЛЛ: каждый элемент УЖЕСТОЧАЕТСЯ

  Мягче → Строже
  Подразумеваемое → Явное
  Произвольной длины → В бюджете токенов
  7 блоков → 8 секций

Потому что:
  • Нет человека для контроля
  • Каждая ошибка × 1000 вызовов
  • Каждый лишний токен × 1000 вызовов
```

# Часть 4. Три ловушки — усиленные для скиллов

Те же три ловушки из грамматики промптинга, но в скиллах они **опаснее**:

```
┌──────────────────┬────────────────────┬──────────────────────┐
│ Ловушка          │ В промпте          │ В скилле (× 1000)    │
├──────────────────┼────────────────────┼──────────────────────┤
│ Омонимия         │ 1 неточный ответ   │ 1000 разных          │
│ "сервис" = ?     │ → переспросите     │ интерпретаций        │
│                  │                    │ → никто не заметит   │
├──────────────────┼────────────────────┼──────────────────────┤
│ Пресуппозиция    │ Модель «найдёт»    │ 1000 ложных находок  │
│ "найди баг"      │ несуществующий баг │ → 1000 галлюцинаций  │
│                  │ → вы увидите       │ → никто не заметит   │
├──────────────────┼────────────────────┼──────────────────────┤
│ Импликатура      │ Модель пропустит   │ 1000 пропусков       │
│ "production-     │ логирование        │ → 1000 неполных      │
│  ready"          │ → вы добавите      │   результатов        │
└──────────────────┴────────────────────┴──────────────────────┘

Решение одно: ЭКСПЛИКАЦИЯ.
В скилле ВСЁ важное должно быть сказано ЯВНО.
```

# Часть 5. Чек-лист на одной странице

## Для промпта

```
□ Есть роль? ("Senior Python Developer")
□ Есть контекст? ("Python 3.12, FastAPI, pytest")
□ Задание конкретное? (сигнатура функции, не описание)
□ Есть ≥2 ограничения? ("Без Counter. Без regex.")
□ Указан формат? ("JSON: {code, tests}")
□ Есть образец ввод→вывод?
□ Есть проверка? ("Пустая строка → {}?")
□ Нет омонимов?
□ Нет пресуппозиций?
□ Нет импликатур? (всё важное ЯВНО)
```

## Для скилла

```
□ Все 8 секций на месте?
□ ANTI-PATTERNS перед CAPABILITIES?
□ VALIDATION в конце?
□ На английском?
□ ≤ 150 токенов (главный файл)?
□ NEVER для критичного? (не "желательно"!)
□ Шаблон в OUTPUT FORMAT? (не описание!)
□ Примеры по ссылке? (не inline!)
□ Нет омонимов?
□ Каждый пункт VALIDATION проверяемый? (да/нет)
```

# Финал: 10 правил, которые изменят ваши промпты и скиллы

```
╔════════════════════════════════════════════════════════════╗
║                                                            ║
║  1.  Явное > подразумеваемого.                             ║
║      Не «production-ready», а конкретный список.           ║
║                                                            ║
║  2.  Запрет > приказа.                                     ║
║      «Без pandas» сужает сильнее, чем «используй numpy».   ║
║                                                            ║
║  3.  NEVER > MUST > SHOULD > «желательно».                 ║
║      «Желательно» = «необязательно» для модели.            ║
║                                                            ║
║  4.  Шаблон > описания.                                    ║
║      Модель ЗАПОЛНЯЕТ шаблон. ИНТЕРПРЕТИРУЕТ описание.     ║
║                                                            ║
║  5.  Конкретное > абстрактного.                            ║
║      «systemd unit» > «сервис». Всегда.                    ║
║                                                            ║
║  6.  Порядок секций = порядок внимания.                    ║
║      Запреты → в начало. Проверка → в конец.               ║
║                                                            ║
║  7.  Английский скилл = -40% токенов.                      ║
║      Думайте по-русски, пишите по-английски.               ║
║                                                            ║
║  8.  Ссылка = 3 токена. Inline = 300 токенов.              ║
║      @examples/file.yaml. Всегда.                          ║
║                                                            ║
║  9.  150 токенов — не ограничение, а дисциплина.           ║
║      Не влезает? → Модули.                                 ║
║                                                            ║
║  10. Скилл пишется один раз. Ошибается — тысячу.           ║
║      Относитесь строже, чем к промпту.                     ║
║                                                            ║
╚════════════════════════════════════════════════════════════╝
```
